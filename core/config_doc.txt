
1. The libc functions libnetblocker actually interposes

libnetblocker (ld_preloader/netblocker.c) defines exactly five hooks with
default visibility. Everything else in the library is hidden, so no other
symbol can take the place of a program's own.

| Stage             | Hook                | What it does                                                     |
| ----------------- | ------------------- | --------------------------------------------------------------- |
| Name resolution   | `getaddrinfo()`     | Refuse a lookup of a host no rule covers (EAI_FAIL); cache the   |
|                   |                     | addresses a permitted lookup returned.                          |
| Outgoing connect  | `connect()`         | Refuse a TCP or connected-UDP peer no rule covers (EACCES).     |
| Local TCP bind    | `bind()`            | Refuse a TCP bind to a local address no [bind] rule covers      |
|                   |                     | (EACCES); only while a [bind] rule exists, and only for TCP.    |
| UDP datagram      | `sendto()`          | Refuse a datagram whose destination no rule covers (EACCES).    |
| UDP datagram      | `sendmsg()`         | The same, for a destination named in `msg_name`.                |

There is NO hook on `socket()`, `listen()`, `accept()`/`accept4()`,
`send()`/`recv()` or `read()`/`write()`. libnetblocker sees outbound name
resolution, outbound connect, the local address of a TCP bind, and the two ways
an unconnected UDP socket names its destination. It does not filter inbound
connections, and it is defence in depth that a raw system call steps around, as
SECURITY.md says.


2. Where the policy comes from

The allow-list is the [connect] section of a policy cfg (see the README's
configuration format), turned into two things: concrete TCP ports handed to
Landlock as `--connect-tcp`, and host/address rules handed to libnetblocker
through the NETBLOCKER_CONF rules file. Landlock enforces the ports below user
space; libnetblocker narrows by host as defence in depth. There is no
`openConnections` / `sendData` / `receiveData` toggle: a rule either names a
host and a port or it does not.

The [bind] section is turned the same way: its ports become Landlock `--bind-tcp`
rules, and its local addresses reach libnetblocker's bind hook through the
NETBLOCKER_BIND_CONF rules file, which narrows a TCP bind to the local addresses
the policy names.
