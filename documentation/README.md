# Phobos Documentation

This site is built with [Docusaurus](https://docusaurus.io/) and published to
<https://ls1intum.github.io/phobos/>.

It is split into two guides:

- **User Documentation** (`docs/user/`) — for whoever puts a program in the sandbox: what
  Phobos protects against, how to run a command under it, and every section of a policy file.
- **Contributor Documentation** (`docs/contributor/`) — for people working on Phobos itself: the
  technologies it is built on, the discovery phase and the subsystems.

## Installation

Use Node 24 or newer, the line CI uses. `.nvmrc` selects it for nvm:

```bash
nvm use                          # nvm install first if you do not have Node 24 yet
pnpm install --frozen-lockfile
```

`pnpm-workspace.yaml` sets `engineStrict`, so `pnpm install` stops with a clear message on a
Node below the `engines` floor (`>=24.18.0`) rather than failing confusingly later in the
build. pnpm 10 and newer read the `packageManager` field themselves and bootstrap the pinned
version, so no separate activation step is needed; where your pnpm is older, run
`corepack enable` first.

CI takes the Corepack route explicitly (`corepack enable && corepack install`) rather than
relying on that bootstrap, because the runner's pnpm is whatever the Node image ships and the
build should not depend on which of the two paths it happens to take.

## Local development

```bash
pnpm start
```

This starts a local development server and opens a browser window. Most changes are reflected
live without restarting.

## Build

```bash
pnpm run build     # static site into build/
pnpm run serve     # serve the built site locally
pnpm run lint      # ESLint over the site sources, then the writing rules
pnpm run typecheck # TypeScript check
```

The build runs with `onBrokenLinks` and `onBrokenAnchors` set to `throw`, so a dangling
cross-reference fails the build rather than shipping. Run `pnpm run build` before pushing.

## Tests

```bash
pnpm run test:install   # one-time: install the Chromium shell
pnpm run test           # Playwright integration tests against the built site
pnpm run test:structure # the twelve Policy Reference pages still share one example
```

These drive the built site in a browser, so they check what a reader actually gets. The
Docusaurus build proves that every link resolves; it does not prove that a page renders. The
suite covers navigation between the two guides, the red marking on the policy reference pages,
the Simple Story boxes, search, the 404 page, and the promise in the privacy statement that
nothing is loaded from a third party.

## The writing rules

```bash
pnpm run test:prose     # the scanner's own tests
pnpm run lint:prose     # the rules, over the Markdown syntax tree
pnpm run report:prose   # every finding, enforced and advisory, as JSON
pnpm run prose:accept   # rewrite the baseline and the advisory ceilings
```

`scripts/prose/rules.mjs` says which rules fail a build and which are reported and left to a
person, and why the line falls where it does. A rule may only be enforced where its forbidden
form is decidable from the text alone.

The enforced rules are carried from the Ares 2 documentation so that the two sister sites read
alike, with two changes for this repository: the canonical term for the thing inside the
sandbox is "the sandboxed command", and the abbreviation list is the one these pages use.

`prose:accept` is run deliberately, in the same commit as the change that earns it, never to
make a build green.

## Writing pages

- Use the `.md` extension for ordinary prose. `markdown.format` is set to `detect`, so `.md` is
  parsed as CommonMark and bare `<` or `{`, which the policy grammar and the shell usage lines
  are full of, need no escaping.
- Use `.mdx` only where a page genuinely needs JSX or an imported React component. MDX rules
  then apply to the whole file.
- Ordering in the sidebar comes from `sidebar_position` front matter and `_category_.json`
  files. Both sidebars are autogenerated, so a new page needs no edit to `sidebar-*.ts`.
- Every page opens with a `:::tip[Simple Story]` admonition: the same idea in plain words,
  before the detail.
- The twelve Policy Reference pages share one example policy file and mark the section each
  page documents in red, through the `policy-focus` magic comment declared in
  `docusaurus.config.ts`. The twelve copies are held identical by `pnpm run test:structure`,
  which strips the markers and compares them, and which checks that each page marks its own
  section and no other. Edit the example on one page and that test tells you about the other
  eleven.
