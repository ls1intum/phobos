    prune_java_egress, under the egress profile, is the one layer-pruner service with a network:
    it keeps or drops the hosts an exercise declared, and the orchestrator does not merge its output.


    The Python container and the orchestrator mount the host directory read-write at /var/tmp.
    The Java containers mount only what they need from it: the exercises and the helpers
    read-only, path_sets read-write, and verify_java the merged opt/core/config read-only.

    The Java container (the layer pruner) writes one java_<exercise>.cfg and its .json record
    per exercise into path_sets; the Python container (Bubblewrap) one python_<exercise>.paths
    and its .json.

    The orchestrate service then holds every artefact to its record, folds the Python path sets
    into python_union.paths, merges each language's exercises into BaseLanguage-<lang>.cfg (no
    [limits]), writes each Java exercise's limits (and whatever the base lacks, which for a union base is
    nothing) to exercises/java_<exercise>.cfg,
    and writes BasePhobos.cfg and TailPhobos.cfg into opt/core/config. The verify_java service
    then runs every Java exercise under that base and its exercise file and writes
    path_sets/verify/. Copying the result into core/config is a reviewed step of its own.

No docker cp and nothing over a network: the shared bind mount is the only channel between them.
